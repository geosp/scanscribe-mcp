## Findings

**M1 · Major · docker-compose.yml:15 and :20 · R25, D9 (compose sets `SCANSCRIBE_MCP_PUBLIC_BASE_URL` and the port)**
- **Problem:** the README documents `SCANSCRIBE_MCP_HOST_PORT` as a supported setting. The default public URL, however, is fixed at `http://localhost:8302` and does not follow `HOST_PORT`.
- **Failure scenario:**
  1. A user sets `SCANSCRIBE_MCP_HOST_PORT=9000` in `.env` and leaves `PUBLIC_BASE_URL` unset, as .env.example's commented line invites.
  2. `create_upload_link` returns `http://localhost:8302/upload/<token>`.
  3. Uploads fail, and so do the download URLs of results, because nothing listens on host port 8302.
- **Evidence:** line 15 has `"${SCANSCRIBE_MCP_HOST_PORT:-8302}:8302"`, but line 20 has `${SCANSCRIBE_MCP_PUBLIC_BASE_URL:-http://localhost:8302}`. The README says to set `PUBLIC_BASE_URL` only "when clients reach the host by another name", not another port.
- **Fix:** default the URL to `http://localhost:${SCANSCRIBE_MCP_HOST_PORT:-8302}`, or say in the README that changing the port also needs `PUBLIC_BASE_URL`.
- **Exposing test:** `SCANSCRIBE_MCP_HOST_PORT=9000 docker compose config` shows the mismatched URL.

  - Compose doesn't set `SCANSCRIBE_MCP_DEVICE`, so the server picks the device itself (config.py:41-42: "default: GPU, else CPU").
  - If a future base-image bump drops a library and Paddle can't see the GPU, jobs silently run on `cpu`, and R25 breaks with no failure. notes.md#d9 itself names "a CPU fallback on a GPU host" as a failure mode.
  - Setting `SCANSCRIBE_MCP_DEVICE: gpu:0` in compose would make that a loud failure.
